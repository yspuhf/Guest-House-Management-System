# MASTER PROMPT: COMPLETE END-TO-END APPLICATION TESTING, BUG DETECTION, AND AUTOMATIC RECTIFICATION Act as a Senior QA Automation Engineer, Full-Stack Developer, Software Tester, Security Auditor, and Application Architect. Your task is to perform a COMPLETE end-to-end audit and testing of the entire application, with special emphasis on every possible aspect of sending, receiving, processing, storing, retrieving, and responding to user requests. Do not limit testing to the visible user interface. Inspect the entire application, including frontend, backend, APIs, database, authentication, middleware, server-side processing, integrations, and communication mechanisms. **IMPORTANT: Do not just identify problems. Fix every reproducible issue, implement the necessary corrections, and retest the application until all critical and major issues are resolved.** ## 1. Initial Application Inspection Before making changes: 1. Identify the application architecture, framework, programming languages, and dependencies. 2. Inspect the complete project directory and source code. 3. Identify all user request submission points. 4. Identify all request-receiving endpoints, APIs, controllers, services, and functions. 5. Identify database tables, relationships, and data-storage mechanisms. 6. Identify authentication and authorization mechanisms. 7. Identify external services and integrations. 8. Identify background jobs, queues, notifications, and asynchronous processes. 9. Understand the complete request lifecycle. Do not assume how the application works. Derive the actual workflow from the source code. ## 2. Complete User Request Sending Tests Test every possible method through which a user can submit a request. Test the following: - Normal text requests. - Empty requests. - Requests containing only spaces. - Very short requests. - Extremely long requests. - Requests containing special characters. - Requests containing emojis. - Requests containing HTML. - Requests containing JavaScript. - Requests containing SQL-like input. - Requests containing multiple lines. - Requests containing Unicode and multilingual characters. - Requests containing numbers and symbols. - Repeated submissions. - Rapid consecutive submissions. - Double-click submissions. - Requests submitted using Enter. - Requests submitted using the Send button. - Requests submitted through mobile interfaces. - Requests submitted with slow internet. - Requests submitted during network interruptions. - Requests submitted after session expiration. Verify that every valid request is properly validated and submitted without data loss. ## 3. Request Receiving and Backend Processing Tests Verify that the backend correctly receives and processes every submitted request. Test: - Correct API endpoint. - HTTP GET, POST, PUT, PATCH, and DELETE handling where applicable. - Correct request headers. - Correct content type. - Correct JSON encoding and decoding. - Correct form-data handling. - Request validation. - Parameter validation. - Authentication verification. - Authorization verification. - Middleware execution. - CSRF protection. - Session handling. - Request sanitization. - Backend exception handling. - Database transaction handling. - Timeout handling. - Concurrent request processing. Verify that the backend never silently drops a valid request. ## 4. User Request and Response Verification Test the complete communication lifecycle: 1. User submits a request. 2. Frontend validates the request. 3. Request reaches the backend. 4. Backend processes the request. 5. Required database operations execute. 6. Backend generates a response. 7. Response reaches the frontend. 8. Frontend correctly displays the response. 9. User can continue the conversation or submit another request. Verify: - Correct response is returned. - Responses are not mixed between users. - Responses are not duplicated. - Responses are not truncated. - Responses are displayed in the correct order. - Error responses are meaningful. - Loading indicators work correctly. - Success indicators work correctly. - Failed requests can be retried. - Previous requests and responses are preserved where expected. - Conversation history is retrieved correctly. ## 5. Database Testing Inspect all database operations associated with user requests. Test: - Record insertion. - Record updating. - Record deletion where authorized. - Record retrieval. - Duplicate records. - Missing records. - Invalid foreign keys. - Null values. - Empty values. - Database connection failures. - Database timeout. - Concurrent writes. - Transaction rollback. - Data consistency. - Character encoding. - Database constraints. - Data persistence after logout and login. Ensure that data belonging to one user is never exposed to another user. Never delete existing production data during testing. ## 6. Authentication and User Management Testing Test: - User registration. - Login. - Logout. - Invalid credentials. - Password validation. - Session expiration. - Session renewal. - Password reset. - Unauthorized requests. - User role restrictions. - Admin permissions. - Access to protected endpoints. - Direct URL access. - Multiple simultaneous sessions. Ensure that users can access only their authorized information. ## 7. API and Communication Testing Test all available APIs and communication channels. For every endpoint, verify: - Correct URL. - Correct HTTP method. - Valid parameters. - Invalid parameters. - Missing parameters. - Correct response status codes. - Correct response structure. - Response time. - Error handling. - Authentication requirements. - Rate limiting. - Request size limits. - Concurrent requests. Test API behavior using automated test scripts and appropriate tools. ## 8. Frontend and User Interface Testing Test the entire application interface. Check: - All buttons. - All forms. - All input fields. - All dropdown menus. - All links. - All navigation menus. - All modals and popups. - All submission controls. - All response displays. - All validation messages. - All loading indicators. - All error messages. Verify responsive behavior on: - Desktop computers. - Laptops. - Tablets. - Android devices. - iPhones. Check different screen resolutions and browser compatibility. ## 9. Security Testing Perform a comprehensive security assessment. Test for: - SQL injection. - Cross-site scripting (XSS). - Cross-site request forgery (CSRF). - Broken authentication. - Broken access control. - Insecure direct object references. - Session hijacking risks. - Sensitive information exposure. - Improper input validation. - File upload vulnerabilities, if applicable. - API abuse. - Brute-force attempts. - Rate-limit bypass. - Insecure error messages. - CORS misconfiguration. Follow secure development practices and OWASP recommendations. Do not perform destructive attacks or test against external systems without authorization. ## 10. Performance and Stress Testing Test application performance under different workloads. Run controlled tests with: - 1 concurrent user. - 5 concurrent users. - 10 concurrent users. - 25 concurrent users. - 50 concurrent users. - 100 concurrent users, if the test environment supports it. Measure: - Request response time. - Average processing time. - Maximum response time. - Failed request percentage. - Database response time. - Memory consumption. - CPU utilization. - Server resource consumption. Identify bottlenecks and optimize inefficient code and database queries. Do not overload production servers. ## 11. Error and Failure Scenario Testing Intentionally simulate failures in a safe test environment. Examples: - Internet disconnected during submission. - Backend server temporarily unavailable. - Database unavailable. - API returns HTTP 400. - API returns HTTP 401. - API returns HTTP 403. - API returns HTTP 404. - API returns HTTP 422. - API returns HTTP 429. - API returns HTTP 500. - API returns HTTP 502. - API returns HTTP 503. - Request timeout. - Invalid JSON response. - Empty API response. - Unexpected server response. - Expired authentication token. Verify that the application recovers gracefully and provides useful error messages. ## 12. Automated Testing Implementation Create or improve automated tests using the framework and testing tools already appropriate for the project. Include: - Unit tests. - Integration tests. - API tests. - Backend tests. - Frontend tests. - End-to-end tests. - Database tests. - Authentication tests. - Security tests. - Regression tests. Automate repetitive test scenarios wherever practical. Ensure that tests are repeatable and can be executed again after future code changes. ## 13. Do not remove existing functionality to make a test pass. Do not disable validation, authentication, security checks, or error handling to hide failures. ## 14. Verify that existing application features still work. Continue fixing and retesting until all critical and major reproducible issues are resolved. ## 16.
